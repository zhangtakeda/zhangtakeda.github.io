Fusion Plasma Integrated Modeling

让物理过程可组合、可微分、可追溯

FusionPRIME 是面向聚变等离子体集成建模的 Python 平台。它把 veqpy、vtspy、mcdpy 以及后续物理过程组织成边界明确的 State、Module、Workflow 与 History，并以 OpenMDAO 作为多模块执行和总导数底座。

Immutable State Composable Module OpenMDAO-backed Linear History Pre-implementation proposal

01 · Overview

三层领域职责，一套数值执行底座

领域对象从数值运行时中分离：Energeia 说物理语言，Harmonia 组织并验收过程，Theoria 面向用户呈现状态与流程。

OpenMDAO 不是第四个领域层。它是 Harmonia 唯一的多 Module 调度、非线性/线性求解和全局导数传播底座。

第一阶段明确支持

  • 单机、单进程、共享内存
  • Module | Bundle | Cycle 的线性 Workflow
  • setup 前固定拓扑和主要 shape
  • 内存中的 append-only History

第一阶段明确不做

  • 分布式调度和运行时动态图
  • History branch / fork / checkout / restart
  • 自研全局导数或 primal reactive scheduler
  • 把任意 State 自动映射为 IMAS / OMAS

02 · Execution & publication

草稿可以覆盖，发布事实永不改写

系统只保留两个生命周期平面。可变性被限制在单次求解中，跨调用 API 只暴露新建的不可变对象。

执行草稿

一次执行期间可覆盖，不具备历史身份。

Worktree Vector LocalStateBuffer KernelWorkspace

已发布事实

验收后新建，发布后不可变，可由 History 追溯。

State Record Result Commit

Workflow 的一次成功运行

STEP 01 History.current 读取已接受的完整 StateMap
STEP 02 Worktree · OpenMDAO 装入、run、solver 与 probes
STEP 03 验收与物化 新建 State、Record 与 Result
STEP 04 commit_batch History 先成为一致性权威
STEP 05 更新最近槽 运行对象复用同一 Result

最近 Result 属于运行对象

module.result · bundle.result · cycle.result

不保存第二份缓存

Node · NodeBinding · Workflow

事务边界：

每个已接受的外层 Node 产生一个 Result 和 Commit。Cycle 内部迭代、 Bundle 子模块以及 FD/CS 探针只写草稿或父诊断，不发布独立事实。

03 · State & values

State 本身就是不可变 API 值

不再引入平行的 StateSnapshot 类型。所有公共 API 数据值使用 frozen=True, slots=True 的 dataclass，公开的嵌套容器和数组同样需要深度不可变。

State：数组不参与递归相等比较

@dataclass(frozen=True, slots=True, eq=True)
class EquilibriumState:
    snapshot_id: SnapshotId
    psi: FrozenArray = field(compare=False, hash=False)
    pressure: FrozenArray = field(compare=False, hash=False)
    schema_version: str = field(compare=False)

Result：事实身份与大型 payload 分离

@dataclass(frozen=True, slots=True, eq=True)
class Result:
    result_id: ResultId
    record: Record = field(compare=False, hash=False)
    outputs: FrozenMap[StatePath, State] | None = field(
        compare=False,
        hash=False,
    )
对象 语义 eq=True 的生产用途
StatePath / FieldPath / config / StateVector 小型合同值 精确相等、映射查找与编译缓存键
State / Record / Result / Commit 带稳定身份的已发布事实 只比较稳定 ID；不递归比较数组或诊断 payload
三个概念必须分开：

数值近似相等需要显式字段、单位、容差与 NaN 规则；存储去重需要内容摘要； Workflow 是否执行和 History 是否新增版本，都不由 State.__eq__ 决定。

04 · Energeia

一个物理过程，从领域对象降到数值 ABI

Module 是用户可独立配置、运行和诊断的完整物理过程。Adapter 是唯一翻译层，Kernel 只接受固定数值合同。

State物理数据、单位、shape 与不变量
Module策略、验收、fallback 与诊断解释
Adapter单位、坐标、dtype、layout 与 push/pull
Kernel固定数值 ABI、局部残差与导数

Module 双入口

evaluate() 是唯一物理计算入口；独立 solve() 与 Workflow 复用相同验证、诊断和物化规则。

Adapter 唯一翻译

State API 与 Kernel ABI 之间的单位、布局和 tangent/cotangent 映射不分散到其他层。

Kernel 不感知领域

Kernel 不认识 State、Module、Workflow 或 History，只处理显式的数值输入、配置与 workspace。

Kernel API 值内容
KernelTopology静态规模、布局、索引、残差维度和实现族
KernelInstance本次物理输入、边界、源项和显式初值
KernelConfig非物理求解控制和已数值化模式
KernelResult数值输出、状态码、收敛信息和小型诊断

独立 Module 不需要 OpenMDAO

06 · History

线性 Commit 序列，加按 StatePath 分列的版本

History 不是树，也不是运行时。StateCatalog 固定槽位顺序；每个 Commit 通过不可变 StateVector 选择各版本列中的 State，从而表达提交后的完整状态。

Commit 执行事实 StateVector (E, P, Q) 本次新增版本
C0INIT(0, 0, 0)E0 · P0 · Q0
C1VEQ Result(1, 0, 0)E1
C2Bundle Result(1, 1, 1)P1 · Q1
C3Cycle Result(2, 1, 1)E2
StatePath E
E0→E1→E2
StatePath P
P0→P1
StatePath Q
Q0→Q1
Commit → Result回答“这次执行发生了什么”
StateVector → 版本列回答“提交后完整 State 是什么”
  • 成功 outputs 追加到对应版本列，未变化 State 沿用 HEAD 下标。
  • 失败 Result 不追加 State，复用本次 run 起点的 StateVector。
  • commit_batch() 在 staging 中完整推演后一次公开整个 batch。
  • Commit 不保存 parent；序列位置是唯一顺序权威。

08 · Invariants

实现可以变化，边界不能漂移

下面是介绍页保留的核心不变量；完整清单和边界细节见 Markdown 原文。

  1. Module 只通过声明端口访问 State，不依赖 OpenMDAO 或 History。
  2. Adapter 是 State 与 Kernel ABI 的唯一翻译层。
  3. evaluate() 只修改执行草稿，不发布事实。
  4. 每次已接受的外层执行都新建 Result，不修改旧对象。
  5. Bundle 和 Cycle 各只有一个外层 Result / Commit。
  6. OpenMDAO 是唯一多 Module 执行、Cycle 求解和全局导数引擎。
  7. History 只接收 Result，以线性 Commit 和版本列保存状态。
  8. 失败 run 不提交成功前缀，也不发布半成品 State。
  9. 所有公共 API 数据值必须是 frozen / slots dataclass。
  10. Module / Bundle / Cycle 各持有一个最近 Result 槽；Node、Binding、Workflow 不复制。

Summary

五条边界足以理解 FusionPRIME

  1. State 是物理语言；Worktree 和 LocalStateBuffer 只是可覆盖草稿。
  2. Module 定义过程，Adapter 翻译，Kernel 只做固定数值计算。
  3. Workflow 线性组织外层 Node；Bundle 并行，Cycle 反馈自洽。
  4. 只有验收后的外层执行产生 Result；History 是一致性权威。
  5. Kernel 负责局部导数，OpenMDAO 负责全局传播，导数探针不发布事实。
